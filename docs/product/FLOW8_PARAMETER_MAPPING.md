## How to read this table

- **Status** uses the owner's vocabulary: DOCUMENTED (documented, not implemented), PROTOCOL SUPPORTED (documented and implemented in the app, not hardware verified), HARDWARE VERIFIED (none exist), APP ONLY (none in this table), UNCONFIRMED, UNSUPPORTED.
- **Hardware verification:** a successful driver call (`midiOutShortMsg` returning `MMSYSERR_NOERROR`) is **not** hardware verification. Evidence of a physical effect or a mixer-originated message is required. No such evidence exists in this repository (see the evidence register), so **no row is HARDWARE VERIFIED**.
- **App allowlisted** records whether the application can send the parameter. It is an implementation fact (E03), **never evidence** that the mixer supports it. The **Source** column lists documentary sources only; driver-only logs (E05) appear only in the hardware-verification column.
- **Read support:** no document describes any mixer-to-host parameter message. For every row the app must not claim to read the value from hardware.
- **MIDI channel** is 1-based (1-16). Status byte = `0xB0|(ch-1)` (CC), `0xC0|(ch-1)` (PC), `0x90|(ch-1)` (Note On).
- Source references: **A-p8** = Behringer Quick Start Guide V 1.0, PDF page 8 (MIDI Implementation); **A-p9** = same guide, PDF page 9 (Specifications). Evidence IDs (E01...) are defined in `FLOW8_EVIDENCE_REGISTER.md`. Conflict IDs (C-01...) in `FLOW8_UNRESOLVED_CONFLICTS.md`. CueAir is not a source for any row.
- Safety levels (NORMAL, ELEVATED, GATED, DISABLED, FORBIDDEN) are defined in `FLOW8_SAFETY_POLICY.md`.
