# Show Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One hold on the main top bar runs `MC` or `BAND`: an ordered macro list that writes only the parameters it lists, cut-down first, with one undo step.

**Architecture:** A pure module compiles a mode (list of steps) into an ordered list of change-plan changes. A JSON store keeps the two modes on the host. The LAN hub gets two actions (`saveShowMode`, `runShowMode`); `runShowMode` stages and commits through the existing `Flow8Service.stage_change_plan` / `commit_change_plan`, so validation, allowlist, rollback and one-step undo are reused. The web UI adds two hold buttons to the top bar and a Setup page to edit steps.

**Tech Stack:** Python 3.14 stdlib, `unittest`; vanilla JS in `flow8/web_ui/app.js`.

**Spec:** `docs/superpowers/specs/2026-11-19-show-mode-design.md` (approved 2026-11-19)

## Global Constraints

- Show Mode never writes `gain` or `phantom`, and no mode may contain a parameter outside `mute, fader, send_fx1, send_fx2, send_mon1, send_mon2`.
- Values are raw 0-127; mute is boolean (`true` = muted). A step value of `null` means NOT SET; a mode with any NOT SET step must not run.
- No invented default values. Only values the owner stated may ship in templates: FX send 0, instrument mute, MC-mic unmute.
- Hold to run: 450 ms, `attachHold(btn, 450, onDone, onTap)`, for both `MC` and `BAND`. UNDO stays on screen after every run.
- Touch targets >= 44 px; text >= 12 px (see `DESIGN.md`).
- Commits, pushes and PRs only when the owner asks. Do not stage `.impeccable/critique/`. Work on a new branch from updated `main`.
- Test command: `python -m unittest discover -s tests -p "test_*.py"`. Tests must not open a MIDI port (`tests/_no_hardware.py`).

## Review Focus

- Hand-edited or imported `show_modes.json` containing `gain`, `phantom`, EQ, channel 8 or a value outside 0-127: rejected, never run (Task 1, Task 2).
- Values unknown before a run (UNSYNCED): the run still happens, but the response must say how many changes undo cannot restore (Task 3).
- Same mode run twice quickly, or from PC and iPad together: the second run reports 0 applied / all skipped, not an error (Task 3).
- Damaged `show_modes.json`: hub still starts with the templates, shows a load error, and does not overwrite the file until a save (Task 2).
- Boundary rejects one change mid-run: everything already sent is rolled back and the response is an error, not a partial success (Task 3).

### Task 1: Mode model, validation, safe-order compile, templates

**Files:**
- Create: `flow8/show_mode.py`
- Test: `tests/test_show_mode.py`

**Interfaces:**
- Produces:
  - `SHOW_MODE_PARAMETERS: tuple[str, ...]` = `("mute", "fader", "send_fx1", "send_fx2", "send_mon1", "send_mon2")`
  - `class ShowModeError(ValueError)`
  - `validate_mode(mode: Mapping[str, Any]) -> dict` returns `{"id": str, "name": str, "steps": [{"parameter": str, "channels": list[int | str], "value": bool | int | None}]}`; raises `ShowModeError`
  - `unset_steps(mode: Mapping[str, Any]) -> list[int]` indexes of steps whose value is `None`
  - `compile_mode(mode: Mapping[str, Any]) -> list[dict]` ordered dicts `{"channel", "parameter", "value", "reason"}`, directly usable by `flow8.change_plan.make_plan`; raises `ShowModeError` if any step is unset
  - `default_modes() -> dict[str, dict]` keys `"mc"`, `"band"`
- Consumes: nothing from other tasks.

Validation rules: channels are ints 1-7 for every parameter; bus ids `fx1 fx2 mon1 mon2` are allowed only with `fader`; channel 8 (main) is refused. `mute` takes a bool, all others an int 0-127 (bool refused as int). Parameter outside `SHOW_MODE_PARAMETERS` is refused, with a message naming gain/phantom as never allowed. The same (channel, parameter) in two steps is refused. Max 32 steps, max 16 channels per step, name 1-40 chars.

Order rule (my call, spec "Calls made by me"): phase 1 = `mute` with value `True`, and any non-mute step with value `0`; phase 2 = everything else. Stable within a phase (list order, channels in list order).

Templates (channels are my defaults: vocal / MC mic = Ch 1, instruments = Ch 2-6, BGM = Ch 7, FX 1):
- `mc` (name `MC`): `send_fx1` ch [1] = 0; `mute` ch [2,3,4,5,6] = true; `mute` ch [1] = false; `fader` ch [1] = null; `fader` ch [7] = null.
- `band` (name `BAND`): `fader` ch [7] = null; `mute` ch [2,3,4,5,6] = false; `send_fx1` ch [1] = null.
